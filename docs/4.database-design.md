# Database Design

Simproプロジェクトのデータベース設計書です。
PostgreSQL (Supabase) を使用し、Prisma ORM でスキーマを管理しています。

## 概要
- **Database**: PostgreSQL (Supabase)
- **Schema Management**: `prisma/schema.prisma`
- **Migration**: Prisma Migrate

## モデル定義 (Models)

### BlogPost (ブログ記事)
Notionのブログデータベースと同期される記事情報。
- **Key Fields**:
  - `id`: UUID
  - `slug`: URL用スラグ (Unique)
  - `notionPageId`: Notion側のページID (Unique, 同期用キー)
  - `status`: `draft`, `published`, `archived`
  - `isPublic`: 公開フラグ
  - `content`: 本文はDBに保存せず、Notionから取得するか、HTML変換して保存するかは実装依存（現状スキーマには本文フィールドなし）。

### ProductPost (プロダクト情報)
ツール、テンプレート、サービスなどのプロダクト情報。
- **Key Fields**:
  - `type`: `Tool`, `Template`, `Service`
  - `actionType`: `transition` (遷移), `download` (DL)
  - `contentLink`: 外部リンクまたはDLリンク
  - その他のメタデータは `BlogPost` と類似。

### User (ユーザー)
*現状、Prismaスキーマ上に `User` モデルは定義されていません。*
- ユーザー管理は Supabase Auth (`auth.users`) に委ねられています。
- 将来的にアプリ固有のプロフィール情報（ニックネーム、アバター設定など）が必要になった場合、`public.profiles` 等のテーブルを作成し、`auth.users.id` と紐付ける設計が推奨されます。

## リレーションとインデックス
- **Index**: `slug`, `category`, `tags`, `status` など、検索やフィルタリングに使用されるカラムには適切にインデックスが設定されています。
- **Relation**: 現状、テーブル間の明示的なリレーション（Foreign Key）は定義されていません。

## Notion連携仕様
`notionPageId` をユニークキーとして持ちます。
データ同期の際は、このIDを使用して「新規作成」か「更新」かを判断します。
