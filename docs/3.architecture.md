# Architecture & Directory Structure

Simproプロジェクトのアーキテクチャ概要です。
Supabaseをバックエンド（Auth, DB）、NotionをCMSとして利用し、Next.jsでフロントエンドを提供する構成です。

## 技術スタック概要
- **Frontend**: Next.js (App Router), React, TypeScript
- **Backend**: Supabase (PostgreSQL, Auth)
- **CMS**: Notion (via Notion API)
- **ORM**: Prisma

---

```text
│   ├── ui/               # shadcn/ui コンポーネント
│   ├── common/           # ヘッダー・フッター等

```

## アーキテクチャの特徴

### 1. Notion as a CMS
ブログ記事 (`BlogPost`) やプロダクト情報 (`ProductPost`) のマスタデータ管理には Notion を利用しています。
- **Sync Flow**: Notion上のデータを定期的に（またはトリガーにより）取得し、アプリ内のDB (PostgreSQL) にキャッシュ/同期するか、あるいはビルド時/リクエスト時に直接Notion APIを叩いて表示します。
- **Logic**: `lib/blog/notion-client.ts`, `notion-normalize.ts` などに連携ロジックが集約されています。

### 2. Route Groups & Layouts
- `(auth)`, `(landing)`, `(protected)` のようにルートグループ `()` を使用して、レイアウトや責務を分離しています。
- これにより、LPと管理画面で異なるヘッダーを表示するなどの制御が容易になっています。

### 3. Authentication Flow
- **Provider**: Supabase Auth
- **Middleware**: `middleware.ts` にてセッションのリフレッシュ処理を実装。
- **Client**: `lib/supabase/client.ts` (Client Side), `server.ts` (Server Side) を使い分け。

### 4. Database Access
- **Prisma**: データアクセスには主にPrismaを使用。
- **Direct vs Pooler**: `prisma.schema` にて `directUrl` (5432) と `url` (6543/pooler) を設定し、Serverless環境からの接続最適化を図っています。
- **Generated Client**: `lib/generated/prisma` にクライアントを出力する設定になっています。
