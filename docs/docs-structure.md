# Docsフォルダ構成と開発ルール

このファイルでは、ドキュメントの配置場所およびアプリケーション開発におけるコンポーネントの配置ルールを定義します。

## ドキュメント構成 (Docs Structure)

`docs/` フォルダ内は以下のように構成します。

- **`docs/Simpro/`**
  - Simproプロジェクト全体、またはメインプロジェクトに関する設計書を配置します。
  - 例: 全体アーキテクチャ、共通DB設計、API設計など。

- **`docs/[AppName]/`** (例: `docs/Zaiko/`, `docs/JobTrace/`)
  - 個別のアプリケーション（在庫管理、ジョブトレースなど）ごとの設計書を配置します。
  - メインプロジェクトとは独立した仕様や画面設計はここに含めます。

- **ルート直下 (`docs/`)**
  - プロジェクト全体のルール (`project-rules.md`)
  - 進捗管理 (`project-management.md`)
  - 技術スタック (`tech-stack.md`)
  - この構成定義ファイル (`docs-structure.md`)

## アプリケーション開発方針 (Development Guidelines)

コンポーネント（部品）の配置について、以下のルールを遵守してください。

### 1. 共通部品
Simproプロジェクト全体、または複数のアプリケーション間で横断的に使用する汎用的な部品は、共通の場所に配置します。

- **配置場所**: `components/` (ルート直下)
- **対象**: ボタン、UIパーツ、共通ヘッダーなど。

### 2. 個別アプリケーションの部品
特定のアプリケーション（例：「在庫」アプリ、「ジョブトレース」アプリなど）でのみ使用する固有の部品は、そのアプリケーションのディレクトリ直下に配置してください。

- **配置場所**: `app/[appName]/_components/`
  - 例: `app/zaiko/_components/`
  - 例: `app/job-trace/_components/`
- **ルール**: 個別アプリの固有ロジックを含む部品は、ルートの `components/` には混ぜないこと。
