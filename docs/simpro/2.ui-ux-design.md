# UI/UX Design

Simproプロジェクトのデザインシステムおよびコンポーネント実装指針です。

## テクノロジースタック
- **Framework**: Next.js App Router
- **Styling**: Tailwind CSS v4
- **Component Library**: shadcn/ui (Radix UI base)
- **Icons**: Lucide React
- **Theme**: next-themes (Dark/Light mode)

---

## ディレクトリ構造とコンポーネント分類

### 1. UI Primitives (`components/ui/`)
shadcn/ui によって生成された、最小単位のUIパーツ群です。
- **ルール**: 原則として自動生成されたコードを維持し、ロジックは持たせない。スタイル調整は `className` props または `globals.css` の変数で行う。
- **例**: `button.tsx`, `card.tsx`, `dialog.tsx`, `input.tsx`

### 2. Common Components (`components/common/`)
アプリケーション全体、または複数のページで再利用される複合コンポーネントです。
- **例**:
  - `Header.tsx`: グローバルナビゲーション、認証ボタンを含む。
  - `Footer.tsx`: フッターリンク、コピーライト。

### 3. Feature Components (`components/` root or `app/[feature]/_components/`)
特定の機能に紐づくコンポーネントです。
- **ルート配置**: `components/AboutGrid.tsx`, `components/LandingSummary.tsx` など、複数箇所で使う可能性があるが特定機能寄りなもの。
- **コロケーション**: `app/blog/ui/BlogListClient.tsx` のように、ページディレクトリ直下に置くことで関連性を明確にする（推奨）。

## 実装ガイドライン

### Client vs Server
- **Server Components (Default)**: 基本的にすべてのコンポーネントはServer Componentとして記述する。
- **Client Components**: `useState`, `useEffect`, ブラウザイベント (`onClick`など) が必要な場合のみ、ファイルの先頭に `'use client'` を記述する。
  - 例: `ThemeToggle.tsx` (状態を持つ), `BlogListClient.tsx` (インタラクションあり)

### Styling Patterns
- **Tailwind Merge**: `cn()` ユーティリティ（`lib/utils.ts`）を使用して、デフォルトのスタイルとPropsから渡されたスタイルを適切にマージする。

```tsx
import { cn } from "@/lib/utils"

export function MyComponent({ className }: { className?: string }) {
  return <div className={cn("bg-white p-4", className)}>Content</div>
}
```

### テーマ設定 (`app/globals.css`)
- CSS変数 (`--primary`, `--foreground` 等) を使用してカラーパレットを定義。
- ダークモード対応は `.dark` クラスに対する変数オーバーライドで実現している。
