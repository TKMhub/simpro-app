# API Design & Data Fetching

Simproプロジェクト（Next.js App Router）におけるAPI設計、Notion連携、データ取得の指針です。

## 基本方針 (Principles)
1. **Server Actions (Mutation)**: データの作成・更新は `lib/[feature]/actions.ts` に定義した Server Actions を使用する。
2. **Data Fetching (Query)**: Server Components から `lib/[feature]/data.ts` (または `utils.ts`) を経由してデータを取得する。
3. **Notion as CMS**: ブログやプロダクト記事のマスターデータは Notion で管理し、API経由で取得またはDBに同期して利用する。

---

## 1. Server Actions (Mutations)
ユーザー操作によるデータ更新や、管理者機能としてのデータ同期処理に使用します。

- **配置場所**: `lib/[feature]/actions.ts` (例: `lib/blog/actions.ts`, `lib/product/actions.ts`)
- **主な役割**:
  - データベースへの書き込み (Prisma)
  - Notion API との連携
  - キャッシュの再検証 (`revalidatePath`)

```typescript
// 例: lib/blog/actions.ts
'use server'
import { prisma } from '@/lib/db/prisma';
import { revalidatePath } from 'next/cache';

export async function syncBlogPosts() {
  // Notionからデータを取得し、Prisma経由でDBを更新する処理など
  // ...
  revalidatePath('/blog');
}
```

## 2. Data Fetching Strategy
### Notion連携 (CMS)
記事データはNotionをソースとしています。
- **Client**: `lib/blog/notion-client.ts` 等の専用クライアントを使用。
- **Normalization**: NotionのRawデータを `notion-normalize.ts` 等でアプリ扱いやすい形式に変換する。
- **Caching**: Notion APIのレスポンスは変更頻度が低いため、適切にキャッシュ戦略を取る（またはDB同期済みのデータをPrismaから引く）。

### Prisma Data Access
- **配置**: `lib/[feature]/[feature]Data.ts` など (例: `lib/blogData.ts`)
- **生成場所**: Prisma Clientは `lib/generated/prisma` に出力されているため、importパスに注意する。

## 3. Route Handlers
現在、`app/api/` は積極的に使用していませんが、以下の用途で使用を検討します。
- Webhook受信 (Notion更新通知など)
- 外部システム向けの公開API

## 4. エラーハンドリング
- Server Actionsでのエラーは、UI側でハンドリングしやすいオブジェクト形式で返す。
- `try-catch` でラップし、予期せぬエラーはログ出力する。
